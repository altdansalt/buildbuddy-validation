# Released CAS chunk state conformance

Run `bb remote test //tests/statemachine/cas-chunk-state/... --test_output=errors`.
The fixture starts digest-pinned v2.314.0 app and cache proxy containers; exact
image references are logged and preserved in harness artifacts. The CLI is the
checksum-verified released 5.0.492 binary, downloaded only on the test runner.
All component traffic uses fixture-local endpoints and disposable credentials.

The reference model stores full bytes and ordered chunk digests. Each endpoint
uses distinct deterministic 3 MiB content in the default namespace (the released
CLI download parser does not preserve arbitrary instance prefixes). Configured
512 KiB average chunks place the blob above the 4x chunking threshold and below
the advertised 4,000,000-byte batch limit. UNKNOWN is the protocol's valid
unspecified chunking function: content-verified arbitrary boundaries are accepted
by this release, without falsely claiming they were generated by FAST_CDC_2020.

| RPC | State transitions and read surfaces | Release behavior |
| --- | --- | --- |
| SpliceBlob | Absent blob; upload valid chunks; publish mapping; repeat identical publication; replace with valid smaller boundaries. After each publication: SplitBlob, ordered chunk ByteStream reads and full digest reconstruction, FindMissingBlobs, BatchReadBlobs, ByteStream.Read, bb download, Cache.GetMetadata; app UI GetCacheMetadata through gRPC and cookie-authenticated HTTP | Implemented; all supported reads must match the model |
| SplitBlob | Repeated mapping reads after each publication and replacement | Reads an existing manifest, not an on-demand splitting mutation |
| RegisterChunkMapping | Valid registration of existing verified chunks; recheck every surface afterward | Explicit Unimplemented; not advertised as supported |
| GetChunkMapping | Valid mapping read after each transition | Explicit Unimplemented, forwarded by proxy |

CAS has no public delete RPC or mutable blob contents: replacement changes the
mapping for the same verified digest, not its content. There is no web UI mapping
API or CLI mapping command. The cache proxy registers Cache.GetMetadata but no
BuildBuddyService/UI metadata API. Cross-component mapping convergence is outside
this item's ownership. Publication/readback is synchronous on each endpoint;
no polling or sleeps are needed.

Metadata is a physical CAS-entry view, not a logical manifest-presence oracle.
For every chunk, its digest size must match through all available metadata
surfaces. For the full blob, metadata may return NotFound if only the manifest
and chunks exist, or the correct size if proxy reads have warmed a physical full
entry. App gRPC and HTTP UI metadata must agree with the cache metadata service.
This documented storage distinction is not classified as a product defect.

## Source enumeration (released v2.314.0)

- `proto/remote_execution.proto`: CAS unary/streaming chunk contracts and cache capabilities.
- `server/remote_cache/content_addressable_storage_server/content_addressable_storage_server.go`:
  SpliceBlob stores a content-verified manifest; SplitBlob loads it and validates
  chunk availability; streaming mapping methods return Unimplemented.
- `server/remote_cache/chunking/chunking.go`: thresholds, manifest storage and
  reconstruction fallback; `server/remote_cache/capabilities_server/capabilities_server.go`:
  unary support and FastCDC parameters advertised.
- `enterprise/server/content_addressable_storage_server_proxy/content_addressable_storage_server_proxy.go`:
  unary and streaming forwarding; `enterprise/server/cmd/cache_proxy/cache_proxy.go`:
  public Cache service registration.
- `server/cache_server/cache_server.go`, `server/buildbuddy_server/buildbuddy_server.go`,
  `proto/cache.proto`, `proto/cache_service.proto`, `proto/resource.proto`:
  physical metadata and UI delegation. Test-local minimal wire encoding follows
  these released schemas without adding shared generated-proto dependencies.
- `cli/download/download.go`: ordinary ByteStream download, default-namespace
  resource parsing. No mapping CLI exists.
