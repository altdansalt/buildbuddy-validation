# Closing an unfinished ByteStream Write omits the response message

Title: Closing an unfinished ByteStream Write omits the response message
Components: app
Image version/digest: enterprise-v2.314.0; gcr.io/flame-public/buildbuddy-app-enterprise@sha256:ed321abe352bc7fa58101e979ff13fd153ccef98a3609e44aef4075848629843
Severity: medium
Severity justification: Clients closing a partial write cannot receive committed progress and instead see an INTERNAL transport error. Combined with unavailable QueryWriteStatus this obstructs protocol-based resumable uploads. No invalid blob publication is demonstrated.
Status: confirmed
Repro test target: //tests/app/bytestream:unfinished_response_bug_test
BuildBuddy invocation: https://app.buildbuddy.io/invocation/ba690695-8ccb-40a3-9a9e-ce7cfce7b599

## Expected behavior

The [Write contract](https://github.com/googleapis/googleapis/blob/master/google/bytestream/bytestream.proto)
says: "When the client closes the request channel, the service will respond
with a WriteResponse." `finish_write` controls finalization, not whether the
response exists. After sending five bytes and closing the request channel
without `finish_write`, a response should report committed progress (which may
be zero if partial progress is discarded); the blob must remain incomplete.

## Actual behavior

A fresh write sends one valid first request with five bytes, then normally
half-closes the request channel using `CloseAndRecv`. The server ends the RPC
without a response message. gRPC reports `INTERNAL` with a cardinality violation.
This test does not cancel the context or break the network, so the missing
response is not caused by cancellation.

Both independent uncached runs reproduced the same result with fresh isolated
app containers, the harness default SQLite/Pebble configuration, self-auth, and
fixture-provisioned API keys. No image overrides or external services were used.
The passing regression suite verifies normal upload/readback, valid EOF reads,
invalid negative ranges, and interrupted-upload restart:
https://app.buildbuddy.io/invocation/db4b574f-7b68-499d-9679-46aaff49b411.
The RPC is made directly through the generated ByteStream client, not through a
proxy or the harness transfer helper.

Reproduction 1: https://app.buildbuddy.io/invocation/ba690695-8ccb-40a3-9a9e-ce7cfce7b599
Reproduction 2: https://app.buildbuddy.io/invocation/f791cc30-f14d-42a6-ab8f-a361e7ae59ba


## Notes

Run `GIT_CONFIG_GLOBAL=/dev/null bb remote test //tests/app/bytestream:unfinished_response_bug_test --test_tag_filters=bug --nocache_test_results`.

The [released Write loop](https://github.com/buildbuddy-io/buildbuddy/blob/v2.314.0/server/remote_cache/byte_stream_server/byte_stream_server.go#L802)
returns nil on `Recv() == io.EOF`, without `SendAndClose`. It sends a response
only after processing `finish_write`. Partial data need not be retained, but a
response message is required. The regression suite separately checks that
canceled partial writes do not publish data and can restart at zero.
Independent verification is recorded below.

## Verification

Verdict: **confirmed**. Both runs failed with `INTERNAL` and the identical
"received no response message from non-server-streaming RPC" cardinality error.
The client sent a valid offset-zero first request containing five bytes for a
larger fresh blob, omitted `finish_write`, then half-closed via `CloseAndRecv`.
There was no cancellation or network interruption. The regression controls
successfully exercised finalized writes and restart after cancellation.

The [ByteStream Write contract](https://github.com/googleapis/googleapis/blob/f5f34cc12374c1b3c11240e3d733b34ad0f63f49/google/bytestream/bytestream.proto#L66)
requires a WriteResponse when the client closes the request channel and separately
requires `finish_write` for completion. REAPI permits early success for already
present blobs, but this fresh fixture has no such blob. The test allows zero
committed bytes, so it does not assume partial data must persist. The release's
[Write loop](https://github.com/buildbuddy-io/buildbuddy/blob/v2.314.0/server/remote_cache/byte_stream_server/byte_stream_server.go#L802)
returns nil on request EOF without `SendAndClose`; its
[writeHandler](https://github.com/buildbuddy-io/buildbuddy/blob/v2.314.0/server/remote_cache/byte_stream_server/byte_stream_server.go#L725)
only creates a response on `finish_write`. Returning OK with no response violates
RPC cardinality independently of the QueryWriteStatus finding. Even if a server
rejected unfinished writes with an explicit error, silent OK without a message
would still be defective.

Severity remains **medium** for broken orderly partial-write handling and
progress reporting. No corruption or publication of partial data is established:
the reproducer stops at the missing-response assertion, before its final
nonpublication check. Restarting at zero is supported by separate controls.
